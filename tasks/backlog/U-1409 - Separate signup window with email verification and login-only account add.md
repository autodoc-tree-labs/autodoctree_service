# U-1409 - Separate signup window with email verification and login-only account add

## Context
- 현재 워크스페이스 런처의 "다른 계정 추가" 영역에서 로그인/회원가입이 동시에 노출되어 UX가 복잡하다.
- 사용자 요구사항은 런처에서는 로그인만, 회원가입은 별도 창에서 이메일 인증코드 입력 기반으로 진행하는 것이다.

## Goal
- 런처의 계정 추가는 로그인 전용으로 단순화하고, 회원가입은 독립 화면에서 인증코드 기반 2단계 플로우로 제공한다.

## Non-goals
- 소셜 로그인
- 회원 프로필 편집

## Scope
- 워크스페이스 런처
  - "다른 계정 추가" 클릭 시 로그인 폼만 노출
  - 회원가입 탭 제거
  - "회원가입" 버튼은 별도 경로(`/signup`)로 이동
- 인증 화면
  - `/login`: 로그인 전용
  - `/signup`: 이메일/비밀번호 입력 -> 인증코드 발송 -> 인증코드 입력 -> 가입 완료
- 에러 메시지 현지화(코드 만료/오입력/메일 전송 실패 등)

## API / Contracts
- 신규 가입 플로우는 `/auth/register/request-code`, `/auth/register/verify` 사용
- 계정 추가 로그인은 `/auth/login`만 사용

## DB / Index changes
- 없음 (백엔드 티켓 B-1405에서 처리)

## Happy path
1. 사용자가 런처에서 "다른 계정 추가"를 열고 로그인 정보 입력
2. 계정이 세션 목록에 추가되고 워크스페이스 목록 동기화
3. 회원가입이 필요하면 별도 `/signup` 화면으로 이동
4. 인증코드 검증 후 계정 생성/로그인 완료

## Edge cases
- 인증코드 미발송 상태에서 verify 시도
- 비밀번호 불일치/길이 부족
- 인증코드 만료/오입력
- 이미 가입된 이메일

## Acceptance Criteria
- [ ] 런처 내 계정 추가는 로그인만 지원한다.
- [ ] 회원가입은 `/signup` 별도 화면에서만 진행된다.
- [ ] 가입은 인증코드 검증 성공 시에만 완료된다.
- [ ] 가입 완료 후 즉시 계정 세션이 추가되고 워크스페이스로 진입한다.

## Testing
- web-user e2e/컴포넌트 수준 시나리오
  - 런처 로그인 전용 표시 검증
  - `/signup` 단계 전환(코드 발송 -> 검증) 검증

## Observability
- 클라이언트 오류 패널에 사용자 친화 메시지 표시
- 비밀번호/코드는 상태 외부로 로그 출력 금지

## Rollout / Rollback
- 롤아웃: `/signup` 라우트 추가 후 런처 회원가입 제거
- 롤백: 기존 런처 회원가입 UI 복원

## Security / Privacy
- 인증코드/비밀번호는 브라우저 콘솔 출력 금지
- 인증 API 실패 메시지에서 계정 존재 여부 과다 노출 방지
